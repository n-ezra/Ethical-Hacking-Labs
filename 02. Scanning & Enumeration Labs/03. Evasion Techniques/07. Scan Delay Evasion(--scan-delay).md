# 🎭 Nmap Scan Delay Evasion Scan (--scan-delay) Analysis

## 📌 Overview

This project demonstrates the use of **Nmap Scan Delay (`--scan-delay`)**, an evasion technique that introduces a delay between probe packets during a scan.

By slowing down the scanning rate, this technique attempts to evade Intrusion Detection Systems (IDS), Intrusion Prevention Systems (IPS), and rate-limiting security controls that may detect or block rapid scanning activity.

---

## 🧪 Command Used

```bash
sudo nmap -sS --scan-delay 10ms 192.168.22.130
```

---

## ⚙️ Command Explanation

| Component | Description |
|-----------|-------------|
| `sudo` | Runs the command with root privileges |
| `nmap` | Network scanning tool |
| `-sS` | Performs a TCP SYN (Stealth) Scan |
| `--scan-delay 10ms` | Waits 10 milliseconds between probe packets |
| `192.168.22.130` | Target IP address |

---

### 🎭 Scan Delay Status

* Nmap successfully introduced a **10ms delay** between probe packets.
* The scan was intentionally slowed down to reduce the likelihood of triggering security monitoring systems.
* SYN Stealth Scan was performed while applying the specified delay.

---

### 🚫 Port Status

* All **1000 default TCP ports** were scanned.
* Every scanned port was reported as **Filtered**.
* No open or closed ports were identified.

---

### ⚠️ What Does "Filtered" Mean?

A filtered state indicates that:

* Firewall rules blocked the scan traffic.
* Security devices silently dropped probe packets.
* Nmap could not determine whether ports were open or closed.

Since no responses were received, all scanned ports were categorized as **filtered**.

## 🚀 Why This Happens

Possible reasons all ports appear filtered:

* Host-based firewall blocking incoming probes.
* Network firewall silently dropping packets.
* IDS/IPS filtering scan traffic.
* ACL restrictions preventing access.
* Security devices inspecting traffic regardless of scan speed.

---

## 🛡️ Security Insight

The `--scan-delay` option is useful because:

* Reduces scan aggressiveness.
* Helps avoid rate-based IDS/IPS detection.
* Makes scanning activity less obvious.
* Useful when scanning networks with strict monitoring systems.

However:

* It only changes the timing of probes.
* It does not bypass firewall rules.
* Modern security solutions can still detect slow and stealthy scans.
