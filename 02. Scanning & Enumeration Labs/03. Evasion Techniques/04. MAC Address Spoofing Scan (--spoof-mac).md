# 🎭 Nmap MAC Address Spoofing Scan (--spoof-mac) Analysis

## 📌 Overview

This project demonstrates the use of **Nmap MAC Address Spoofing (`--spoof-mac`)**, an evasion technique that changes the attacker's MAC address during a scan.

MAC spoofing is commonly used during **penetration testing** to hide the real network interface identity and bypass security controls that rely on MAC-based filtering.

---

## 🧪 Command Used

```bash
sudo nmap -sS --spoof-mac 0 192.168.22.130
```

---

## ⚙️ Command Explanation

| Component | Description |
|-----------|-------------|
| `sudo` | Runs the command with root privileges |
| `nmap` | Network scanning tool |
| `-sS` | Performs a TCP SYN (Stealth) Scan |
| `--spoof-mac 0` | Generates a random MAC address |
| `192.168.22.130` | Target IP address |

## 🔎 Result Analysis

### ✅ Host Status

* Target host **192.168.22.130** is reachable.
* Host responded with a latency of **0.046 seconds**.

---

### 🎭 MAC Address Spoofing Status

* Nmap successfully generated and used a spoofed MAC address:

```text
31:E2:C1:21:3F:0B
```

* The spoofed MAC address does not belong to any registered hardware vendor.
* The real MAC address of the scanning machine was hidden during the scan.

---

### 🚫 Port Status

* All **1000 default TCP ports** were scanned.
* Every scanned port was reported as **Filtered**.
* No open or closed ports were identified.

---

### ⚠️ What Does "Filtered" Mean?

A filtered state indicates that:

* Firewall rules are blocking probe packets.
* Security devices are silently dropping traffic.
* Nmap cannot determine whether ports are open or closed.

Because no responses were received, Nmap categorized all scanned ports as **filtered**.

---

## 🔐 Key Observations

* MAC spoofing was successfully applied.
* The target host remained reachable.
* The target did not reveal any open services.
* Firewall or packet filtering mechanisms prevented port-state determination.
* MAC address obfuscation did not bypass the target's security controls.

---

## 🚀 Why This Happens

Possible reasons for all ports being filtered:

* Host-based firewall blocking scan traffic.
* Network firewall filtering SYN packets.
* IDS/IPS systems detecting and dropping probes.
* Access Control Lists (ACLs) restricting connections.
* Security policies preventing responses to unknown traffic.

---

## 🛡️ Security Insight

MAC spoofing is useful because:

* Hides the real hardware identity of the attacker.
* Helps test MAC-based access controls.
* Can evade simple network monitoring systems.
* Makes attribution more difficult in local network environments.

However:

* MAC spoofing only affects Layer 2 communication.
* It does not bypass properly configured firewalls or IDS/IPS solutions.
* Modern security controls typically inspect multiple packet attributes, not just MAC addresses.

---

## 🧠 Key Takeaways

* MAC Address Spoofing is an effective reconnaissance evasion technique.
* The scan successfully concealed the scanner's original MAC address.
* The target host is alive but heavily filtered.
* No accessible TCP services were identified.
* MAC spoofing alone is insufficient to bypass strong network defenses.

---

## 🏁 Conclusion

This scan demonstrates that:

* Nmap successfully performed a SYN Stealth Scan using a spoofed MAC address.
* The target host **192.168.22.130** is online and responsive.
* All scanned TCP ports were filtered by security controls.
* MAC address spoofing helped hide the scanner's identity but did not reveal additional information about the target.
