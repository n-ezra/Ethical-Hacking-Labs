# 🎭 Nmap Custom Data Length Scan (--data-length) Analysis

## 📌 Overview

This project demonstrates the use of **Nmap Custom Data Length (`--data-length`)**, an evasion technique that appends random data to probe packets during a scan.

Adding extra data changes the packet size and signature, making it harder for some intrusion detection systems (IDS) and packet-filtering devices to identify scanning activity based on standard Nmap packet patterns.

---

## 🧪 Command Used

```bash
sudo nmap --data-length 50 192.168.20.130
```

---

## ⚙️ Command Explanation

| Component | Description |
|-----------|-------------|
| `sudo` | Runs the command with root privileges |
| `nmap` | Network scanning tool |
| `--data-length 50` | Appends 50 bytes of random data to each probe packet |
| `192.168.20.130` | Target IP address |

### ⚠️ What Does "Filtered" Mean?

A filtered state indicates that:

* Firewall rules blocked the probe packets.
* IDS/IPS or security devices dropped traffic silently.
* Nmap could not determine whether ports were open or closed.

Because no responses were received, Nmap classified all scanned ports as **filtered**.

Possible reasons all ports appear filtered:

* ACLs restricting access to services.
* Security devices inspecting packet contents rather than relying only on packet size.

---

## 🛡️ Security Insight

The `--data-length` option is useful because:

* It modifies the signature of Nmap probe packets.
* Helps test IDS/IPS detection capabilities.
* Can bypass simple signature-based detection mechanisms.
* Makes scan traffic appear less predictable.

However:

* Modern firewalls and IDS/IPS solutions analyze packet behavior, not just packet size.
* Adding random data does not guarantee firewall or IDS evasion.
