# 🎭 Nmap Source Port Scan (--source-port) Analysis

## 📌 Overview

This project demonstrates the use of **Nmap Source Port Manipulation (`--source-port`)**, an evasion technique that sends scan packets using a specified source port.

In this scan, source port **53 (DNS)** was used because some firewalls and filtering devices may trust or allow traffic originating from common service ports such as DNS.

This technique is commonly used during **penetration testing** to test firewall filtering rules and identify potential misconfigurations.

---

## 🧪 Command Used

```bash
nmap --source-port 53 192.168.22.130
```

---

## ⚙️ Command Explanation

| Component | Description |
|-----------|-------------|
| `nmap` | Network scanning tool |
| `--source-port 53` | Sends scan packets using source port 53 (DNS) |
| `192.168.22.130` | Target IP address |

## 🔎 Result Analysis

### ✅ Host Status

* Target host **192.168.22.130** is reachable.
* Host responded with a latency of **0.045 seconds**.

---

### 🚫 Port Status

* All **1000 default TCP ports** were scanned.
* Every scanned port returned a **Filtered** state.
* No open or closed ports were identified.

---

### ⚠️ What Does "Filtered" Mean?

A filtered state indicates that:

* Packets are being blocked by a firewall.
* Security devices are silently dropping scan probes.
* Nmap cannot determine whether ports are open or closed.

Because no response was received, Nmap categorizes the ports as **filtered**.

---

### 🔐 Key Observations

* Source port **53 (DNS)** was successfully used.
* The target remained reachable throughout the scan.
* Despite using a trusted service port, the firewall still blocked or dropped scan packets.
* No evidence suggests that source-port spoofing bypassed the target's filtering controls.

---

## 🚀 Why This Happens

Possible reasons all ports appear filtered:

* Host-based firewall blocking incoming connections.
* Network firewall dropping unsolicited packets.
* IDS/IPS security controls filtering scan traffic.
* ACL (Access Control List) restrictions.
* Firewall does not trust traffic solely based on source port number.

---

## 🛡️ Security Insight

Using source port 53 is a classic evasion technique because:

* DNS traffic commonly uses port 53.
* Some legacy firewalls allow DNS-related traffic.
* Misconfigured filtering devices may trust packets from well-known service ports.

However, modern security devices inspect traffic more deeply and do not rely only on source port numbers.

---

## 🧠 Key Takeaways

* Source Port Scan is an **evasion technique**, not a vulnerability.
* Changing the source port does not guarantee firewall bypass.
* The target host is alive but appears heavily filtered.
* Modern firewalls can detect and block such techniques effectively.
* No open ports were discovered during this scan.

---

## 🏁 Conclusion

This scan demonstrates that:

* The target host **192.168.22.130** is online.
* Source port **53 (DNS)** was used successfully.
* All scanned ports were filtered and produced no response.
* The target environment appears protected by firewall or packet-filtering mechanisms.
* Source port manipulation alone was insufficient to reveal any accessible services.
