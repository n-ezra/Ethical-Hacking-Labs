# 🎭 Nmap MTU Fragmentation Scan (--mtu) Analysis

## 📌 Overview

This project demonstrates the use of **Nmap MTU Fragmentation (`--mtu`)**, an evasion technique that fragments scan packets into smaller pieces using a specified MTU (Maximum Transmission Unit) value.

Packet fragmentation can sometimes help bypass poorly configured firewalls and packet filtering devices that fail to properly reassemble fragmented packets before inspection.

---

## 🧪 Command Used

```bash
sudo nmap -sS -Pn --mtu 32 192.168.22.130
```

---

## ⚙️ Command Explanation

| Component | Description |
|-----------|-------------|
| `sudo` | Runs the command with root privileges |
| `nmap` | Network scanning tool |
| `-sS` | Performs a TCP SYN (Stealth) Scan |
| `-Pn` | Skips host discovery and treats target as online |
| `--mtu 32` | Sends fragmented packets with an MTU size of 32 bytes |
| `192.168.22.130` | Target IP address |

### ⚠️ What Does "Filtered" Mean?

A filtered state indicates that:

* Firewall rules blocked the scan probes.
* Network security devices silently dropped packets.
* Nmap did not receive enough information to determine port status.

As a result, Nmap classified all scanned ports as **filtered**.

## 🚀 Why This Happens

Possible reasons all ports appear filtered:

* Stateful firewall dropping fragmented packets.
* IDS/IPS detecting fragmented scan traffic.
* Router or gateway filtering fragmented packets.
* Host firewall rejecting unsolicited TCP probes.
* Security devices reassembling and inspecting fragmented traffic before filtering it.

---

## 🛡️ Security Insight

Packet fragmentation is used because:

* Some legacy firewalls inspect only the first packet fragment.
* Security devices may fail to reassemble fragmented packets correctly.
* Fragmentation can sometimes evade simple packet-filtering mechanisms.

However:

* Modern firewalls and IDS/IPS solutions typically reassemble fragmented packets before inspection.
* Fragmentation alone rarely bypasses well-configured security controls.
