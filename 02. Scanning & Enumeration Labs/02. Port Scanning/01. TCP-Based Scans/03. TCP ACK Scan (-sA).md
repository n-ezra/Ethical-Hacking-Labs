# 📡 TCP ACK Scan (-sA) – Nmap Analysis Report

## 🔍 Executive Summary

This report presents the results of a TCP ACK Scan (`-sA`) conducted using Nmap against the target **192.168.56.1**.

The objective of an ACK scan is not to discover open ports, but to determine whether ports are **filtered or unfiltered** by a firewall. The scan results indicate that the target host is reachable and responding to ACK probes.

- Determine whether ports are filtered or unfiltered

| Parameter | Description |

---

## 🔬 Scan Methodology

TCP ACK Scan works differently from SYN or Connect scans.

### Process:

1. Nmap sends a TCP ACK packet to the target port.
2. If the port is **unfiltered**, the target responds with an **RST (Reset)** packet.
3. If no response is received or an ICMP filtering message is returned, the port is considered **filtered**.

### Purpose

ACK scans are primarily used for:

- Firewall detection
- Packet filtering analysis
- Rule-set mapping
- Network security assessment

> ⚠️ ACK Scan cannot determine whether a port is open or closed.

## 🛡️ Security Interpretation

- No firewall analysis could be performed.

- No port-state information was collected.

The scan terminated during the host discovery phase.

---



### Why Use `-Pn`?

`-Pn` tells Nmap:

> "Assume the host is online and proceed directly to port scanning."

This is useful when:

- ICMP Echo Requests are blocked
- Host discovery probes are filtered
- Firewalls hide systems from ping-based detection

---

## ⚖️ Advantages of ACK Scan

- Detects firewall filtering rules
- Maps packet-filtering behavior
- Useful for firewall enumeration
- Generates less suspicious traffic than some scans

---

## ❌ Limitations

- Cannot identify open ports
- Cannot identify services
- Depends on target responses
- Host discovery failures prevent meaningful results

A TCP ACK Scan is designed for **firewall detection**, not port discovery. If host discovery fails, Nmap cannot analyze filtering behavior unless the scan is forced with `-Pn`.
