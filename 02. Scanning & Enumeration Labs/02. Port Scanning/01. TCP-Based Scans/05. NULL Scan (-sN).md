# 📡 NULL Scan (-sN) – Nmap Analysis 

## 🔍 Executive Summary

This report presents the results of a TCP NULL Scan (`-sN`) conducted using Nmap against the target **192.168.56.1**.

The objective of a NULL scan is to identify open and closed TCP ports by sending TCP packets with **no flags set**. This technique is commonly used for stealth reconnaissance and firewall testing. ## 🔬 Scan Methodology

NULL Scan sends TCP packets with **all TCP flags turned off**.

### Process

1. Nmap sends a TCP packet with no flags set.
2. According to RFC 793:
   - Closed ports respond with an **RST (Reset)** packet.
   - Open ports ignore the packet and send no response.
3. If no response is received, Nmap classifies the port as **open|filtered**.
4. If an ICMP filtering message is received, the port is considered filtered.

### Purpose

NULL scans are primarily used for:

- Stealth port scanning
- Firewall testing
- Packet-filtering analysis
- Reconnaissance activities

## 🔐 Meaning of "open|filtered"

A port is classified as **open|filtered** when:

- No response is received.
- Nmap cannot determine whether:
  - The port is open, or
  - A filtering device blocked the packet.

### Common Causes

- Firewall filtering
- Packet dropping
- Open ports ignoring NULL probes
- Security appliances
- IDS/IPS protections

## ⚖️ Advantages of NULL Scan

- Stealthier than traditional scans
- Useful for firewall testing
- Generates less obvious traffic patterns
- Can bypass poorly configured packet filters

---

## ❌ Limitations

- Often blocked by modern firewalls
- Produces ambiguous open|filtered results
- Less reliable than SYN scans
- Not effective against many Windows systems
- Cannot directly identify services
