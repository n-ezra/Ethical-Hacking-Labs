This report presents the results of a TCP Xmas Scan (`-sX`) conducted using Nmap against the target **192.168.56.1**.

The objective of an Xmas scan is to identify open and closed TCP ports by sending specially crafted packets with the **FIN, PSH, and URG flags set simultaneously**. This stealth scanning technique is often used to bypass basic filtering mechanisms and analyze firewall behavior.

## 🔬 Scan Methodology

Xmas Scan sends TCP packets with the following flags enabled:

```text
FIN + PSH + URG
```

The packet is called an **Xmas packet** because multiple flags are "lit up" like Christmas tree lights.

### Process

1. Nmap sends a TCP packet containing FIN, PSH, and URG flags.
2. According to RFC 793:
   - Closed ports respond with an **RST** packet.
   - Open ports ignore the packet and send no response.
3. If no response is received, Nmap marks the port as **open|filtered**.
4. ICMP unreachable messages may indicate filtering.

### Purpose

Xmas scans are commonly used for:

- Firewall testing
- Stealth reconnaissance
- Packet-filtering analysis
- Security assessments

## 🔐 Meaning of "open|filtered"

A port is classified as **open|filtered** when:

- No response is received.
- Nmap cannot determine whether:
  - The port is open, or
  - A filtering device blocked the packet.

### Common Causes

- Firewall filtering
- Silent packet drops
- IDS/IPS protections
- Open ports ignoring Xmas packets
- Packet-filtering security devices

- Stealthier than traditional TCP scans

## ❌ Limitations

- Frequently blocked by modern firewalls
- Produces ambiguous open|filtered results
- Less reliable than SYN scans
- Not effective against many Windows-based systems
- Cannot directly identify services
