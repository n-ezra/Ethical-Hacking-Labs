# 📡 UDP Scan (-sU) – Nmap Analysis Report

## 🔍 Executive Summary

This report presents the results of a **UDP Scan (`-sU`)** conducted using Nmap against the target **192.168.56.1**.

The objective of this scan is to identify active UDP services and evaluate the network exposure. The results indicate that all scanned UDP ports are **open|filtered**, suggesting strong packet filtering or lack of response from the target system.

---

## 🎯 Objectives

* Identify open UDP ports and services
* Analyze port states (open, closed, open|filtered)
* Evaluate network-level filtering
* Document findings in a professional format

---

## ⚙️ Scan Configuration

### 🔧 Command Used

```bash
sudo nmap -sU 192.168.56.1
```

---

## 🧠 Command Explanation

| Parameter      | Description                               |
| -------------- | ----------------------------------------- |
| `sudo`         | Required for UDP scan (raw packet access) |
| `nmap`         | Network scanning and reconnaissance tool  |
| `-sU`          | UDP Scan                                  |
| `192.168.56.1` | Target IP address                         |

---

## 🔬 Scan Methodology

UDP Scan operates using connectionless communication:

1. UDP packet → Sent to target port
2. ICMP Port Unreachable ← Received → **Port is CLOSED**
3. No response → **OPEN or FILTERED**
4. Valid UDP response → **Port is OPEN**

## 🛡️ Security Interpretation

The results strongly indicate:

* UDP probes are **not receiving responses**
* Presence of:

  * Firewall filtering UDP traffic
  * Packet dropping mechanisms
  * Disabled or hidden UDP services

### 🔐 Meaning of "open|filtered"

A port is marked as **open|filtered** when:

* No response is received
* Nmap cannot determine if the port is open or blocked

👉 This is very common in UDP scans due to:

* Silent packet drops
* Lack of acknowledgment mechanism

## ⚖️ Advantages of UDP Scan

* Identifies UDP-based services
* Completes overall network assessment
* Detects services missed by TCP scans

---

## ❌ Limitations

* Slower and less reliable than TCP scans
* High ambiguity (**open|filtered state**)
* Easily blocked by firewalls
* Results require careful interpretation
