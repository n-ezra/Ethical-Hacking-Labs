## 📌 Overview

This project demonstrates **UDP-based host discovery using Nmap (-PU)** to identify active hosts within a network.

The objective of this scan is to evaluate host availability using UDP probes and analyze behavior when the target does **not respond**, indicating potential filtering or host inactivity.

## 📡 Technical Background

### 🔹 UDP-Based Host Discovery

UDP scanning works by sending **UDP packets to specific ports** on the target system.

### 🔹 Response Behavior

| Response Type         | Interpretation               |
| --------------------- | ---------------------------- |
| ICMP Port Unreachable | Host is **UP**               |
| UDP Service Response  | Host is **UP**               |
| No Response           | Host is **DOWN or FILTERED** |

> ⚠️ UDP is a **connectionless protocol**, making detection less reliable compared to TCP or ARP.

## 🔍 Command Explanation

| Option      | Description                                           |
| ----------- | ----------------------------------------------------- |
| `-sn`       | Performs host discovery only (disables port scanning) |
| `-PU`       | Enables UDP Ping                                      |
| `53,67,123` | Target UDP ports (DNS, DHCP, NTP)                     |
| `sudo`      | Required for raw packet transmission                  |
| Target      | `192.168.56.1`                                        |

## 📌 Key Findings

* ❌ **Host Not Detected**
  No response was received from the target host.

* ⛔ **No ICMP Feedback**
  Expected ICMP "Port Unreachable" message was not observed.

* ⏳ **Increased Scan Duration**
  UDP scans typically take longer due to lack of immediate responses.

---

## 🔍 Interpretation

The result indicates one of the following scenarios:

1. **Host is Down**
   The system may be powered off or disconnected.

2. **Firewall Filtering**
   UDP packets are being silently dropped by firewall rules.

3. **ICMP Disabled**
   The system is configured not to send ICMP error responses.

---

## ⚠️ Limitations of UDP Host Discovery

| Limitation          | Impact                                   |
| ------------------- | ---------------------------------------- |
| ICMP Dependency     | Requires ICMP responses for confirmation |
| Silent Packet Drops | Leads to false negatives                 |
| Slow Performance    | Longer scan times compared to TCP        |

## 💡 Conclusion

UDP-based host discovery is a valuable but **less reliable technique** due to its dependency on ICMP responses. In real-world scenarios, it should be used alongside TCP and ARP-based methods to ensure accurate host detection.
