# ICMP Address Mask Request (-PM) Using Nmap – Practical Analysis

## 📌 Executive Summary

This project demonstrates the use of **ICMP Address Mask Request (`-PM`)** in Nmap for host discovery. The scan highlights a real-world scenario where the target host does not respond, emphasizing the limitations of this legacy technique in modern networks.

---

## 🧠 Technical Background

ICMP Address Mask Request is an older ICMP mechanism:

* **Type:** 17 (Address Mask Request)
* **Reply Type:** 18 (Address Mask Reply)

It was originally designed to allow a host to discover its **subnet mask (netmask)** from another device.

---

## ⚙️ Command Executed

```bash
nmap -sn -PM 192.168.56.1
```

---

## 🔍 Command Breakdown

| Option         | Description                             |
| -------------- | --------------------------------------- |
| `-sn`          | Host discovery only (no port scanning)  |
| `-PM`          | Sends ICMP Address Mask Request packets |
| `192.168.56.1` | Target host                             |

## 🔎 Result Analysis

### Key Observations:

* **Target scanned:** 1 IP address
* **Hosts up:** 0
* **Scan duration:** ~2 seconds

### 🧠 Interpretation:

This result indicates that:

* The target system is either:

  * 📴 Offline
  * 🔒 Blocking ICMP Address Mask Requests
* Modern systems typically **disable this ICMP type**
* Firewalls and security controls prevent such responses

---

## 🚨 Important Insight

Nmap explicitly suggests:

```bash
If it is really up, but blocking our ping probes, try -Pn
```

### What this means:

* The host **may still be alive**
* But it is **not responding to ICMP-based discovery**
* You can bypass this using:

```bash
nmap -Pn 192.168.56.1
```

---

## 🎯 Key Takeaways

* ICMP Address Mask Request is a **legacy and deprecated technique**
* Most modern systems **block or ignore these requests**
* “Host seems down” does **not guarantee the host is offline**
* Effective reconnaissance requires **multiple scanning techniques**
