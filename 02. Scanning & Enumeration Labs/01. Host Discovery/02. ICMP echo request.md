# ICMP Echo Request (-PE) Host Discovery using Nmap

## 📌 Executive Summary

This project demonstrates the use of **ICMP Echo Request (`-PE`)** in **Nmap** to perform host discovery across a subnet. The scan highlights a real-world scenario where **no hosts respond to ICMP**, emphasizing the limitations of traditional ping-based discovery in modern secured networks.

---

## 🧠 Technical Background

The **ICMP Echo Request** is a Layer 3 network diagnostic mechanism:

* **Type:** 8 (Echo Request)
* **Reply Type:** 0 (Echo Reply)
* Commonly known as: **Ping**

Nmap leverages this mechanism using the `-PE` flag to determine whether a host is reachable.

---

## ⚙️ Command Execution

```bash
nmap -sn -PE 192.168.56.1/24
```

### 🔍 Parameter Breakdown

| Option | Description                                          |
| ------ | ---------------------------------------------------- |
| `-sn`  | Disables port scanning; performs host discovery only |
| `-PE`  | Sends ICMP Echo Requests (standard ping)             |
| `/24`  | Targets 256 IP addresses within the subnet           |

## 🔎 Result Analysis

Despite scanning an entire `/24` subnet:

* **Total IPs scanned:** 256
* **Responsive hosts:** 0
* **Scan duration:** ~52 seconds

### 🧠 Interpretation

This outcome strongly suggests:

* ICMP traffic is **filtered or blocked** (firewall/ACL rules)
* Target systems are configured to **ignore ping requests**
* The network environment enforces **stealth or hardened security policies**

---

## 🚨 Security Insight

In modern enterprise environments:

* ICMP Echo Requests are often **disabled** to prevent reconnaissance
* Relying solely on `-PE` may lead to **false negatives**
* Attack surface visibility becomes **limited without multi-method scanning**
