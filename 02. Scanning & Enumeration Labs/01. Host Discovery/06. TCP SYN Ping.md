# Nmap TCP SYN Ping - Host Discovery Analysis

## 📌 Project Overview

This project demonstrates **host discovery using TCP SYN Ping (-PS) in Nmap**.

The objective is to determine whether a target host is active by sending TCP SYN packets to commonly used ports.

## 📡 Technical Background

### 🔹 What is TCP SYN Ping?

TCP SYN Ping sends a SYN packet to specified ports to check if a host is alive.

### 🔹 Expected Behavior:

* **SYN-ACK** → Host is UP (port open)
* **RST** → Host is UP (port closed)
* **No Response** → Host DOWN / filtered

---

## ⚙️ Command Executed

```bash
sudo nmap -sn -PS22,80,443 192.168.56.1
```

## 📌 Key Observations

* ❌ **Host Status** → No active host detected
* ⛔ **No Response** → Target did not respond to SYN packets
* 🔒 **Possible Reason**:

  * Firewall blocking TCP probes
  * Target machine is powered off
  * Ports (22, 80, 443) are filtered

---

## ⚠️ Important Insight

Even if host is actually UP:

* It may **block TCP SYN probes**
* Nmap will show **"Host seems down"**


## ⚖️ TCP SYN Ping Limitations

| Limitation         | Explanation                      |
| ------------------ | -------------------------------- |
| Firewall Filtering | SYN packets may be blocked       |
| Port Dependency    | Requires responsive ports        |
| False Negatives    | Host may appear down incorrectly |

## 💡 Conclusion

TCP SYN Ping is a powerful technique for host discovery, but it depends on port accessibility. In restricted environments, it may produce false negatives, making it important to combine with other techniques like ARP or ICMP scanning.
