# 🔐 Certificate Transparency Analysis using crt.sh

## 📌 Overview

This project demonstrates **passive reconnaissance** using **crt.sh**, a Certificate Transparency (CT) log search tool used to discover SSL/TLS certificates issued for a domain.

Certificate Transparency helps identify:

* Subdomains
* Historical certificate records
* Misconfigured or exposed assets

---

## 🛠️ Tool Used

* **crt.sh** (https://crt.sh)

---

## 🎯 Objectives

* Discover subdomains from SSL certificates
* Analyze certificate issuance history
* Identify potential attack surfaces
* Support OSINT-based reconnaissance

---


## 🔍 How crt.sh Works

crt.sh queries public Certificate Transparency logs and returns:

* Issued SSL certificates
* Associated domain names
* Subdomains linked to certificates

## 🔍 Key Security & Architecture Insights

### 1. Subdomain & Infrastructure Mapping
* **Wildcard Deployments:** Extensive usage of structural wildcards (`*.google.com`, `*.mail.google.com`) demonstrates how core legacy service groups (Docs, Mail, Sites) shared common certificate boundaries during the 2011–2013 era.
* **Regional TLD Expansion:** The `adwords.google.com` certificate showcases dynamic multi-domain optimization using SANs to cover regional localized country code top-level domains (ccTLDs) such as `.com.ar` (Argentina), `.com.br` (Brazil), and `.com.cn` (China) within a single asset profile.

### 2. Historical Asset Lifespans
* Most certificates identified reflect the traditional **1-year to 2-year validity windows** standard during the early 2010s, contrasting with the automated 90-day lifespans used today via modern ACME providers.
* Specialized subdomains like `onex.wifi.google.com` indicate dedicated historical network access endpoints mapped out via historical logs.
